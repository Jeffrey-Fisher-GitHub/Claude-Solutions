## 2. AI regulation and policy

Source: https://eulawlive.com/commission-lays-down-common-rules-for-ai-regulatory-sandboxes/ and https://www.techtimes.com/articles/330540/20261112/eu-ai-regulatory-sandbox-rules-start-december-1-tests-earn-no-compliance-clearance-liability-stays.htm

## 4. Academic articles (arXiv)

Note: summaries come from an auto-generated digest, not the papers themselves; verify before citing. Digest: https://github.com/datnguyenquy94/news-radar/issues/1054

**A Theory of Policy Optimization in Post-Training: Coverage Collapse and Reference Resets**
Source: http://arxiv.org/abs/2611.14467v1
Argues that reinforcement-style post-training can narrow a model to a small slice of its possible outputs, and proposes periodically resetting the reference policy to restore diversity and stability.

**ReTrace: Distilling Tool-Using Agents into Planner-Free Workflows**
Source: http://arxiv.org/abs/2611.14492v1
Targets the cost of agents that call an LLM at every step by distilling a teacher agent's behavior into fixed workflows, reportedly keeping performance on standard operating procedures.

**When Should Agents Remember? Falsification-Gated Self-Evolution for LLM Agents**
Source: http://arxiv.org/abs/2611.14326v1
Proposes saving a lesson to an agent's memory only if the trajectory passes a verifier, to avoid memories that hurt later tasks.

**Precision on Demand: Escalating Weight Bits at Uncertain Decoding Steps**
Source: http://arxiv.org/abs/2611.14418v1
Stores weights at low precision and raises precision only when the output distribution is uncertain, aiming at smaller local models. The digests disagree on the starting bit width, so check the paper.

**Medical Image Segmentation: Foundation Model Adaptation versus Task-Specific Training**
Source: http://arxiv.org/abs/2611.14519v1
Compares adapting a foundation model with training task-specific models and reports the latter stays competitive, especially with scarce or shifted data.

## 5. Java and better code

Source for items 1-3: https://www.happycoders.eu/java/java-28-features/ (Nov 8, 2026). Java 28 is due March 9, 2027; feature set freezes after Dec 3, 2026.

**JEP 401: Value Objects (preview, Java 28)**
Value classes have no identity, so `==` compares field values, removing classic equality surprises and enabling more compact memory layout. A natural hook for teaching value vs. identity.

**JEP 543: Structured Concurrency (final in Java 28)**
StructuredTaskScope treats related subtasks as a unit: if one fails the others are cancelled, reducing thread leaks. Preview flags are no longer needed.

**JEP 540: Simple JSON API (incubator, Java 28)**
A small built-in JSON reader/writer lets students parse JSON without Jackson or Gson; data binding and streaming are explicit non-goals.

**JEP 530: Primitive Types in Patterns, instanceof and switch (4th preview, JDK 26)**
Source: https://www.infoworld.com/article/4050993/jdk-26-the-new-features-in-java-26.html
Extends pattern matching to all primitive types to avoid unsafe lossy casts, with tighter switch dominance checks.

**JEP 500: Warnings for deep reflection that mutates final fields (JDK 26)**
Source: same InfoWorld article
Prepares for making `final` truly final by default; a good lesson on immutability. (JetBrains' Java Annotated Monthly for Nov 2026 could not be fetched.)

## Teaching ideas for CISC 121

1. **Lab: "Should this agent remember?"** Students build a tiny tool-using agent loop (Python or Java) with a memory list, then implement a verifier gate so lessons are stored only after a check passes (inspired by the falsification-gated memory paper). Compare task accuracy with and without the gate, and discuss the Hermes-agent misuse report as a safety case.
2. **Lecture/discussion: Is scaling over?** Use the Stanford AI100 findings, the post-training "coverage collapse" paper, and "precision on demand" quantization to frame a debate on scaling vs. reasoning vs. efficiency. Students chart reported benchmark and price claims (Gemini 4 Carbon, Muse Ember) and practice separating vendor claims from independently verified results.
3. **Lab: Java value vs. identity and structured concurrency.** Students fetch several model-API-style calls in parallel using Java structured concurrency (preview or Java 28 early access) and parse responses with the new JSON API, then compare `==` behavior on records and value records. Tie in the EU sandbox rules by having teams write a one-page "sandbox plan" for their mini-agent describing risks and oversight.
